# Screen spec: the update notice and the "Updates" settings

Status: proposed in the pull request for issue #796 (plan PL7), for
[ADR 0014](../adr/0014-player-updater.md) sections 2, 3 and 5. Design system: [system.md](system.md).
Neighbouring spec: [class-list.md](class-list.md) (the window, its markers, plates and keys, which
this follows). Reference mock-ups and screenshots: [mockups/](mockups/), files `updates-*.html`
(11 mock-ups, generated by [updates-pages.js](mockups/updates-pages.js), styled by
[updates.css](mockups/updates.css) on top of `class-list.css`) and `updates-<state>-<w>x<h>.png`. The CI screenshots of the class list with the notice include one
state with the filter hidden (fewer than the filter's threshold of classes), for U4's 6 rows.
**Where a mock-up and this text differ, the text wins.**

## Purpose

Tell the instructor that a newer version of the player exists, and let them look for one. The
player today only tells (ADR 0014 section 2): the notice shows the version and one button that
opens the release's page in the system browser. Nothing is downloaded or installed, so nothing here
asks for a decision about the running player and nothing here can interrupt a class.

Two places: a **notice on the class list**, and an **"Updates" part of a new Settings page**. It
is read in the computer's own window at arm's length, so it follows the class list's convention
(class-list.md): sizes in pixels, the same tokens, no hue, no motion.

Settled before this spec (issue #796; not reopened here): the notice is outside the class and
never shown while a class is playing or paused mid-class; one button, "Open release page", shown
only when a newer version is available (absent in every other state, never disabled); the status
words are "Up to date", "Newer version available", "Checking…" and "Could not check"; the two
switches are "Check automatically" (on by default) and "Pre-releases" (off by default); no URL is
ever shown or entered.

## Where it sits

- **Settings** is a new page of the player's first window. A key "Settings" (shortcut Ctrl+,
  or Cmd+, on macOS) sits in the class list's header, left of "Open a
  class file…". Settings takes the whole body, as pairing does; "Back to the classes" (Esc)
  returns to the list as it was. Settings holds only "Updates" in this version; the page is the
  place later sections go, each under its own `h2`.
- **The notice** is on the class list only, under the sync status line. It is never on the
  presenter, the room screen, the rider's or the instructor's phone pages.
- **The class gate** (ADR 0014 section 3). While a class is open in the room and presenter windows,
  whether playing, paused, before its start or complete, and whether it is pinned or opened from a
  file, the player shows no notice and no "Settings" key (absent, not disabled), so the page cannot
  be a second way to see the status. A check that ends meanwhile keeps its result; the notice and the key
  come back when the instructor is on the class list with no class pinned (class-list.md, "When
  the room window closes"). The notice then appears without a transition, once.
- **Priority.** A plate that needs the instructor (pairing ran out, the class file could not be
  opened, saved classes unreadable, Swedebeat needs reconnecting) comes first. The notice is shown
  only when no plate is on the list, and takes its place when the plate goes. Pairing, the
  Swedebeat sign-in form and any other panel that takes the body hide it too.

## Content, in priority order

**Notice (class list)**
1. The words "Newer version available" and the new version, as the tag has it ("0.2.0",
   "0.3.0-rc.1"), in Big Shoulders.
2. The word "Pre-release" in an outlined tag beside the version, when it has a hyphen part.
3. The detail "You have 0.1.0. Nothing is downloaded or installed."
4. The one button, "Open release page".

**Settings, "Updates"**
1. The status, with its marker, and "Open release page" at its right when the status is "Newer
   version available".
2. "Current version" and "Latest version" ("Not known" when no check has found one), "Pre-release"
   beside a latest version that is one.
3. "Check now".
4. The switch "Check automatically", then "Pre-releases", each with one line of help.

Nothing else: no release notes, no list of past versions, no date, no size, no checksum, no file
name, no progress, no address of any kind, no "Install" or "Download" (ADR 0014 section 2: the
player downloads nothing). The release page is the place for those.

## Layout

All sizes are CSS pixels of the window's client area, the three of class-list.md: 1920×1080,
1280×800, and 1000×720 (the smallest). The column is at most 1280 px (the list) and 760 px
(Settings), left-aligned under the header, side padding 32 px.

```
Notice, under the status line, above the filter and the list header:

+--------------------------------------------------------------------+
| [#] Newer version available   0.2.0                [ Open release page ] |
|     You have 0.1.0. Nothing is downloaded or installed.             |
+--------------------------------------------------------------------+

Settings:
+--------------------------------------------------------------------+
| Settings                                  [ Back to the classes Esc ] |
| Updates                                                              |
|------------------------------------------------------------------- |
| [#] Newer version available                    [ Open release page ] |
|     Version 0.2.0 is on its release page. Nothing is downloaded...   |
| Current version   0.1.0                                              |
| Latest version    0.2.0                                              |
| [ Check now ]                                                        |
|------------------------------------------------------------------- |
| Check automatically  At start and every 6 hours...        On  (  o) |
| Pre-releases         Also tell me about test versions...  Off (o  ) |
+--------------------------------------------------------------------+
```

| Element | Notice (class list) | Settings |
|---|---|---|
| Container | A bordered strip (2 px `--light-1`, radius 6), 60 px high at least, 10 px under the status line. Not a plate: a plate (white, `role="alert"`) is for what needs the instructor, and a new version does not | The body, in one column |
| Marker | The filled square (below) | The same, in the status line |
| Words | Status words 20 px bold; detail 16 px `--light-2` | Same |
| Version | Big Shoulders 600, 26 px | Same, in the facts rows |
| Button | "Open release page", primary (white), at the right, 44 px high at least, 17 px | Same, in the status row |

At every size the notice is one strip of at most two lines of text; the detail never wraps below
two lines (the longest, "You have 0.10.12-rc.1. Nothing is downloaded or installed.", fits at
1000 px). Settings fits one screen at 1000×720 with no scroll (every state).

**The marker.** The class list's three shapes keep their meaning (filled circle: fine; hollow
circle: working; hollow square: away, a normal state). One shape is added for the state in this
spec: the **filled square** for "Newer version available" (news, nothing is wrong). White, no hue,
always with its words.

### The switches

A row is 72 px high at least, the whole row is the target. A switch is a 60 × 34 px outlined track
with a 22 px knob, and the word "On" or "Off" in 17 px bold at its left: on is a white track with a
black knob at the right, off is an outlined track with a white knob at the left. State is therefore
carried by the word, the knob's side and the fill, never by the fill alone. The knob moves at once.
Help lines (16 px, `--light-2`):

| Switch | Default | On | Off |
|---|---|---|---|
| Check automatically | On | "At start and every 6 hours while the player is open." | "Off: the player looks for a newer version only when you press Check now." |
| Pre-releases | Off | "Also tell me about test versions, which come before a normal release." | Same line |

The help lines are written for an instructor, not for a developer: "test versions", never "release
candidate" or "channel". The version itself shows as the tag has it.

## States

| State | When (bridge status, ADR 0014 section 5) | Notice | Settings status line | "Open release page" |
|---|---|---|---|---|
| **Up to date** | "up to date": nothing newer, or nothing newer on the chosen channel | None | Filled circle, "Up to date", "You have the newest version." Latest version equals current | Absent |
| **Newer version available** | "newer": a strictly higher version | The strip, shown | Filled square, "Newer version available", "Version *x* is on its release page. Nothing is downloaded or installed." | Shown |
| **Checking…** | "checking": at start, every 6 hours, or "Check now" | None. A notice already shown stays until the result replaces it (no flicker to nothing) | Hollow circle, still, "Checking…", "Looking for a newer version." | Absent |
| **Could not check** | "could not check": any failure of the fetch (ADR 0014 section 1) | None. A notice from an earlier check is dropped: the player no longer knows | Hollow square, "Could not check", "The list of releases could not be read. Press Check now to try again." Not a plate: it is a normal state, as Offline on the class list | Absent |
| **Newer pre-release** | "newer" with "Pre-releases" on and the latest a pre-release | As "Newer version available", with the "Pre-release" tag | As "Newer version available", with the tag beside "Latest version" | Shown |
| **Class open** | Any status while a class is open | None; no Settings key | Not reachable | Not reachable |

Notes:

- **The words are the issue's.** No state is renamed, and there is no other state: "Open release
  page" is absent unless the status is "Newer version available".
- **Notice versus status.** The notice shows only for "Newer version available". Every other
  status is visible in Settings only; the class list stays as class-list.md draws it, plus the
  Settings key.
- **Check now.** Pressing it sets "Checking…". While checking it keeps its place in the tab order
  and its look but is dimmed to `--light-2` and has `aria-disabled="true"`, so focus is not lost and a second press does nothing. When the
  check ends, focus stays on it. A result is announced once (below).
- **Pre-releases off with only a pre-release published** reads "Up to date" (ADR 0014 section 1);
  the page says nothing about it.
- **Latest version.** Shown as found by the last check that succeeded; "Not known" before one.
  "Checking…" keeps the earlier value, so the line does not jump.
- **Switch changes** take effect at once and the player checks again when "Pre-releases" is
  changed (the answer may differ); "Check automatically" changes nothing on screen but its own row
  and its help line.
- **No URL.** No address, link text or hint of one is shown or typed anywhere. "Open release page"
  is a button, not a link, so the page has no `href`; the shell opens the page itself
  (ADR 0014 section 2). If the browser cannot be opened, the player says nothing extra in this
  version (see Decisions).

## Keyboard and focus

| Where | Tab order |
|---|---|
| Class list | Settings, Open a class file…, the status key (as class-list.md), **Open release page** (when the notice is shown), the filter, the list, Start |
| Settings | Back to the classes, **Open release page** (only when shown), Check now, Check automatically, Pre-releases |

| Key | Where | Does |
|---|---|---|
| Ctrl+, (Cmd+,) | Class list, with no class open | Opens Settings |
| Esc | Settings | Back to the classes (focus returns to the Settings key) |
| Enter, Space | Buttons | Press |
| Space (also Enter) | A switch | Toggles it; the new state is announced |
| Up, Down | Between the two switches | Not used; the two are separate Tab stops |

Initial focus on opening Settings: "Open release page" when shown, otherwise "Check now". The
switches are `role="switch"` with `aria-checked`, named by their label and described by their help
line. The focus ring is 3 px `--light-1` with 2 px offset (class-list.md), at least 3 : 1 against
its neighbours everywhere. Nothing changes focus by itself: a result arriving never moves it.

## Accessibility

- The status line and the notice are `role="status"` (polite): the words are said once per change,
  "Newer version available, 0.2.0". Neither is an alert; nothing here interrupts.
- Every marker has its words beside it; the shape is not the only carrier. The version and the
  Pre-release tag are text.
- "Open release page" has the accessible name "Open release page" (the visible words), with no
  address.
- Contrast and sizes below. No text is below 14 px. All text is live text, never a picture.
- Reduced motion: there is none to reduce (below).

## Motion

None, so no reduced-motion variant to keep: markers do not spin or pulse (the hollow circle for
"Checking…" stays still), the knob moves at once, the notice and the status words appear and change
without a transition, and the page swaps at once with the operating system's reduced-motion setting
on or off. This is the class list's rule (class-list.md, "Motion").

## Wording

Sentence case, no full stop on a status line or a button, one full sentence for a detail or a help
line (class-list.md, presenter.md). The fixed words, exactly as in the issue: "Up to date", "Newer
version available", "Checking…" (with the ellipsis character), "Could not check", "Check now",
"Open release page", "Check automatically", "Pre-releases", "Updates". Added here: "Settings",
"Back to the classes", "Current version", "Latest version", "Not known", "Pre-release", "On",
"Off", and the detail and help lines above. The words "update", "install" and "download" are not
used for the notice's action: the player does none of them, and "Open release page" says what the
button does. "Updates" names the settings part only.

## Data each element needs

| Element | Source (ADR 0014 section 5) |
|---|---|
| Status words | The update status: one of "up to date", "newer", "checking", "could not check" |
| Current, latest version | The same reply: the current version and the latest version, strings that passed the SemVer check; the Pre-release tag follows from a hyphen in the latest |
| Check now | The bridge's "check now" |
| Open release page | The bridge's "open release page", no argument |
| The two switches | Their stored values, and the two setters (one boolean each; a non-boolean is refused) |
| The class gate | The class-open state the shell already holds (class-list.md, "Where it sits") |

The renderer holds no address, path, feed setting or install control, and shows none.

## Decisions (Orchestrator, on this pull request)

- **Settings key.** Accepted: "Settings" (Ctrl+,) in the class list header. class-list.md carries
  its header, tab order and L3 line; the filled-square marker is in system.md, "Status markers".
- **No feedback when the browser fails to open.** The button simply does nothing; the bridge returns
  no result (ADR 0014 section 5). If it later does, a `role="status"` line "The page could not be
  opened. Try again." goes under the button.
- **Before any check** the status reads "Could not check", as the four states are fixed and no fifth state is added. Its detail line says that no check has run yet (for example "No check has run yet. Press Check now."), not that the list of releases could not be read. The words in `player/app/src/core/update/words.ts` (line 252) and `view.ts` (line 176) still give the failure wording; a screens-lane issue tracks the fix.
- **No dismiss on the notice.** The strip is one line and goes when the player is updated.
