# Screen spec: the room screen's join codes

Status: proposed in the pull request for issue #351, for [ADR 0007](../adr/0007-riders-in-a-live-session.md)
sections 3 and 4 (the new join code, and where riders appear). It adds to the plain 2D room screen
([room-2d.md](room-2d.md)) the two QR codes riders and the instructor scan, and the update when the
instructor makes a new code. Design system: [system.md](system.md). Neighbouring specs:
[rider.md](rider.md) (what the riders' QR code opens), [companion.md](companion.md) (what the
instructor's opens), [riders-panel.md](riders-panel.md) (where New code is pressed). Reference
mock-ups and screenshots: [mockups/](mockups/), files `room-join-*.html` (generated by
[room-join-pages.js](mockups/room-join-pages.js), styled by [join.css](mockups/join.css) on top of
[room.css](mockups/room.css) and [controls.css](mockups/controls.css)) and `room-join-*-<w>x<h>.png`.
**Where a mock-up and this text differ, the text wins.**

## Purpose

Show, on the screen everyone can see, what a phone needs to get into the class: **a QR code for
riders**, **a QR code for the instructor's own phone** and **the join code as text**. Nothing else
about riders is on this screen: no count, no nickname, no list, no lock state (rule 13; ADR 0007
section 4). The room screen's own look and its rules do not change: while no sheet or band is shown,
the screen is exactly the one in room-2d.md.

## The two codes

| Code | Address it carries | Opens | For |
|---|---|---|---|
| Riders' QR code | `https://<site>/j#<join code>` | The rider page ([rider.md](rider.md)), with the code already in the address | Riders, any time the class is joinable |
| Instructor's QR code | `https://<site>/control#<join code>` | The companion page ([companion.md](companion.md)): fills the class code and offers sign-in | The instructor's own phone |

- **Both carry the join code and nothing else** (rule 14). The one-time **control code is never on
  this screen**, in a QR code or as text, and never reaches the room window: it stays on the
  presenter window (ADR 0005, unchanged). The instructor's QR code gives no control by itself; the
  phone still needs the instructor's sign-in.
- The join code is also shown **as text**, `XXXX-XXXX`, labelled "Class code", in the type of a
  value (`--t-value`), so a rider can type it. Under it the site address as text ("Or open
  classbeat.example/j", `--t-minor`), which breaks anywhere rather than being cut if it is long.
- **Encoding.** Each address is at most 42 bytes (QR version 3, level M, 29 modules) so the codes
  stay coarse; a longer site address means a bigger version and is checked against J3 below. A
  QR code is **black on white** with a **4-module quiet zone**, drawn as an image from the address,
  never as text in a picture (an `alt` names what it opens). They are the only white fills on the
  sheet besides the "New code" plate.
- Scanning the wrong one is harmless: a rider who scans the instructor's code gets a sign-in page
  and nothing else. The two are told apart by size and words, not by colour (rule 7): the riders'
  code is the large one under "Join the class"; the instructor's is the small one under
  "Instructor's phone".

## Where the codes show

Two places. They never show the **same** code twice at once, and neither one covers what riders read
while the class runs.

### 1. The join sheet

A sheet over the stage, above the control band and the score. It carries both codes and the text.

| When | Behaviour |
|---|---|
| **Before the start, join codes on** (a live session exists) | Shows by itself. It stays until Start (or the first interval begins): then it closes at once. With one display the band stays under it (Start always in sight, room-2d.md); with a second display the band is hidden as ever and the sheet stands alone |
| **J key, any time** | Toggles the sheet. Before the start J closes it (and brings back the class summary); during the class J opens it for **at most 20 s**, then it closes by itself. The clock goes on underneath, uninterrupted. J does not show the band |
| **Esc** | Closes the sheet before it closes by itself |
| Join codes off, starting, ended, or the app not paired | There is no code: no sheet, and J does nothing |

During a class the sheet hides the zone and the countdown for up to 20 s: it is the instructor's
own press, and it is meant for a pause. That cost is accepted so that the codes can be big enough
to scan from a bike; for a late joiner **without** covering the class, use the band (next).

What the sheet covers: everything between the rail (which stays: class time, segment, music link)
and the band's top, so it covers the gel, the countdown, the metrics, the cue, the next row and the
score's box above the band. Before the start that is the class summary and the first zone, none of
which a rider needs while joining. It lies exactly in the box below and covers nothing else.

### 2. The band's class-code slot

The slot of room-2d.md ("The class code") keeps its place and its states. **Its QR code now carries
the riders' address** (`/j#<join code>`), not the instructor's: a late rider can scan it whenever
the instructor moves the mouse, and the class goes on uncovered. It is the same size as before
(12.4 vh, 10.8 vh at 3:2 and narrower; at least 2 px per module, room-2d.md C10).

- **While the sheet is open the slot has no QR code** (the codes are on the sheet): it shows "Class
  code", the code and the state line **"J hides the codes"** (17 characters, inside room-2d.md's 18).
- The instructor's QR code is only on the sheet. An instructor who needs it during a class presses
  J.
- The slot's other states (Absent, Off, Starting, Refused, No answer, Ended, Reconnecting, Phone
  connected) are room-2d.md's, unchanged. The button's words stay "Phone remote" and "Show the
  class code": one session serves the instructor's phone and the riders.

## Layout of the sheet

All sizes are shares of the screen height, as everywhere (system.md). The box is
`left`/`right` = the safe edge (5 vw), `top` = 11 vh (below the rail), `bottom` = 24 vh up from the
screen's foot (16:9 and wider, the band at 79.5 vh), or 20 vh at 3:2 and narrower (the band at 83 vh):
2 vh clear of the band. It is opaque (`--stage`).

### Wide: 16:9 and 16:10 down to 1.7 : 1 (1920 × 1080)

```
+----------------------------------------------------------------------+
|                                                  ● Waiting for the...|  rail
|  +-----------+   Join the class        |   +------+                  |
|  |           |   [New code]            |   |  QR  |                  |
|  |    QR     |   Scan with your        |   +------+                  |
|  |  riders   |   phone's camera.       |   Instructor's phone        |
|  |   48 vh   |   Class code            |   Scan, sign in and steer.  |
|  |           |   KXPD-RMTB             |   It gives no control ...   |
|  +-----------+   Or open classbeat..   |                             |
|----------------------------------------------------------------------|
|  [Previous] [Start] [Next]              Class code KXPD-RMTB [End]   |  band
+----------------------------------------------------------------------+
```

Two cards in a row, 4 vw apart, the second ruled off with a 0.3 vh `--stage-line` line.

| Part | Size | Type |
|---|---|---|
| Riders' QR code | **48 vh** square (at 1080 lines: 518 px, 14 px a module) | Image, black on white |
| "Join the class" | at the QR's top | `--t-value` Big Shoulders 800 |
| "Scan with your phone's camera." | under it | `--t-minor` Atkinson 700, up to two lines |
| "Class code", the code | under it | label `--t-label`; code `--t-value`, `--light-1` |
| "Or open", the address | under it | label; address `--t-minor` Big Shoulders 600, `--light-2`, up to three lines, breaks anywhere |
| Instructor's card | 26 vw wide; QR **24 vh** square (259 px at 1080 lines) | Heading `--t-minor` Atkinson 700; line `--t-label` `--light-2`, up to four lines |

### Stacked: under 1.7 : 1, 16:10 down to 5:4 (1650 × 1080, 1440 × 1080, 1280 × 1024)

The two cards stack, the riders' first, so the code and the address keep their width:
the riders' QR code is **36 vh** square with its text on its right; under it, ruled off, the
instructor's **20 vh** code with its heading and line on its right. Type sizes are the same.

At 3:2 and narrower the box ends 20 vh above the foot (the band is 12 vh).

## The new code

When the instructor makes a new join code (riders-panel.md, "New code"), the app receives
`join_code` and tells the room window the new code (ADR 0007 section 3). **The screen is redrawn at
once, in one frame**: the riders' QR code, the instructor's QR code, the code as text, the address
and the band slot's QR code are all the new ones. There is **no cross-fade and no moment with the
old and the new code on screen together**: a rider must never scan a code that has stopped working
when a good one could be shown.

- While the sheet is open, a white plate "New code" sits under "Join the class" for **10 s**
  (`--m-state` to come and go; at once with reduced motion). It is white, never a hue. If the
  sheet is not open (a class running, the band hidden) there is nothing to show: the next time
  either place shows a code it is the new one.
- A new code **does not open the sheet** during a class: it would hide the class without the
  instructor asking.
- The old code stops working for joins at once (ADR 0007 section 3); riders already in stay.
- The control code, if the presenter was showing one, ends with the old join code. It was never on
  this screen, so nothing here changes for it.

## Keyboard

One row for room-2d.md's keyboard table:

| Key | Does | On the band |
|---|---|---|
| J | Opens the join sheet for at most 20 s during a class, or toggles it before the start; nothing when there is no code. Does not move the class and does not show the band | No |

While the End question is open, J does nothing (the band is asking). A held key repeats nothing.

## Motion and reduced motion

The sheet appears and goes in `--m-state` (300 ms, ease out); a new code is **not** animated (one
frame, as above). With `prefers-reduced-motion` everything is at once. Nothing flashes.

## Measurable checks

On the mock-ups, [shoot.js](mockups/shoot.js) and [measure.js](mockups/measure.js) run room-2d.md's
checks C1 to C4, C6 and C8 on the join mock-ups at all ten sizes (the main state and the worst
case), plus these; PL4's CI runs the same on the real screen.

| Check | Requirement |
|---|---|
| J1. Text | "Join the class" and the code in the `--t-value` tier: cap height at least **5.5 %** of the screen height (C1); the address and the instructor's heading at the minor tier, at least **3 %**; labels at least **2 %**. Contrast at least 7 : 1 (4.5 : 1 for labels) on `--stage`. All text inside the 5 % safe area |
| J2. Codes are big enough | Riders' QR code at least **48 vh** (wide) or **36 vh** (stacked) high and square; the instructor's at least **24 vh** or **20 vh**. At 720 lines that is at least **7 px per module** for the smaller riders' size (36 vh, 29 + 8 = 37 modules) |
| J3. Coarse codes | The riders' address is at most 42 bytes; a longer address is checked against J2 with its larger version (the modules get smaller) before it ships |
| J4. Black on white | Each QR code is black on white with a 4-module quiet zone, 29 modules, as an image with an `alt`; no hue anywhere on the sheet (C6) |
| J5. Nothing about riders | The sheet and the slot carry no rider count, nickname, lock state or list (rule 13); neither QR code nor any text carries a control code or a token |
| J6. No collisions | No text overlaps another or the codes; the address breaks rather than being cut; nothing is covered by the band, which starts 2 vh below the sheet's box |
| J7. Redraw | In one frame every code on screen is the new one (a test on the real screen, PL4 CI: two screenshots, the second taken the frame after `join_code`, hold no pixel of the old code) |

## What the screen never shows (plan section 3)

| Rule | How this addition keeps it |
|---|---|
| 1. A finished class only | No control beyond room-2d.md's; J shows a sheet and moves nothing |
| 6. None of MOWL's look | A black sheet, two QR codes, the join code as text: no ring, no bar, no per-rider shape |
| 7. Colour means the planned zone | The sheet is white, grey and black; the QR codes are black on white |
| 13. Rider data one way | No rider count, nickname, list, lock state or reading is on this screen or its channel to the room window |
| 14. Join code is a session id only | Both QR codes carry the join code and nothing else; the control code is never on this screen |
| 15. No team games | "Join the class" is an address, not an invitation to a team: no names of others, no totals |

## Needs from the desktop shell

The room window already receives the join code (room-2d.md, "What the room window needs from the
desktop shell"). This adds: the **new** code on the same channel when it changes, and the room
window's own J key and the sheet's 20 s timer, which are in the window. It gets **no** rider data,
no lock state and no control code on any channel; ADR 0005's guard (no control code on a room
channel) and ADR 0007's (the rider list reaches the presenter's channel only) are checked by tests
there.
