# Screen spec: the rider page

Status: proposed in the pull request for issue #351, for PL8's second part (plan section 12) and
[ADR 0007](../adr/0007-riders-in-a-live-session.md) sections 1, 4 and 5. Design system:
[system.md](system.md). Neighbouring specs: [companion.md](companion.md) (the instructor's phone page,
whose gel, chips, keys and checks this page shares), [room-2d.md](room-2d.md) (the class words),
[riders-panel.md](riders-panel.md) and [room-join.md](room-join.md) (the other two screens of this
issue). Reference mock-ups and screenshots: [mockups/](mockups/), files `rider-*.html` (24
mock-ups, generated by [rider-pages.js](mockups/rider-pages.js) from [rider-kit.js](mockups/rider-kit.js),
styled by [companion.css](mockups/companion.css) and [rider.css](mockups/rider.css)) and
`rider-*-<w>x<h>.png`. **Where a mock-up and this text differ, the text wins.**

## Purpose

A web page on a rider's own phone, opened by scanning the QR code on the room screen. Nothing to
install, no account, no sign-in: a code from the address and a nickname. It shows **that rider's
own view, in step with the room**, and nothing else: the interval now, the time left, what comes
next, and the effort for the zone worked out on the phone from the rider's own FTP or maximum heart
rate. The phone is usually on the handlebar, read in glances at 60 to 90 cm while riding, with
sweat and a bouncing view, as the companion is.

The page **sends nothing after it has joined** (ADR 0007 section 1): its only WebSocket message is
`hello`. It has no remote, no key that moves the class, no chat, no reaction. It shows no cue and no
song (`rider_state` carries neither). It **never controls a bike or any equipment** (rule 2) and
connects to no sensor (PL9 comes later, in its own spec).

## What stays on the phone

| Thing | Where it lives | Reaches the server? |
|---|---|---|
| Nickname | The join request body (`nickname`), then the instructor's presenter list in the app's memory | Yes, to the instructor only. It is the one thing about the rider that leaves the phone |
| FTP and maximum heart rate | The page's memory. With "Remember on this phone" on, also `localStorage` | **Never.** No request body and no message has a field for them (ADR 0007 section 1, guard in section 6) |
| Rider token `cbp_rdr_…` | `sessionStorage` only, never the address | Sent in `hello` |
| Class code | The address's fragment, `/j#<code>`, kept there so a lapsed rider can join again from the same tab | Sent once, in the join body |

The nickname is **not** remembered (ADR 0007 names FTP and maximum heart rate only): a rider types
it again each class. That is a default, reversible in the screens issue if the owner wants it.

## Getting in

1. The phone's own camera reads the QR code and opens `https://<site>/j#<code>`. The page reads the
   code from the fragment, **keeps it there**, and shows the entry form with the code as text
   ("Class code KXPD-RMTB") so the rider can check it against the room screen.
2. **No code in the address** (the page was opened without scanning): the form shows a Class code
   field first. It is typed as `XXXX-XXXX`; case, spaces and hyphens are ignored and the shown form
   is sent. A code that is not 8 letters of the alphabet is caught on the page ("Codes are 8
   letters") and never goes out. It is the same join request and the same answers.
3. The rider types a nickname and, if they like, an FTP and a maximum heart rate, and presses
   **Join the class**. The page sends `POST /api/live/join` with `session` and `nickname`, then
   opens the WebSocket and sends `hello` with the rider token.
4. A rider whose token lapsed (the tab was closed, or 5 minutes without a connection) sees the entry
   form again with a plate "You were away too long" and joins again from the same address.

**Fields and limits** (the page's own checks, before anything is sent; a refused value never goes
out and the field keeps what was typed):

| Field | Required | Check | Words when wrong |
|---|---|---|---|
| Nickname | Yes | 1 to 24 characters after trimming spaces at both ends (ADR 0002 section 8) | "Type a nickname, 1 to 24 characters." |
| FTP, in watts | No | A whole number from 50 to 600 | "FTP is a whole number from 50 to 600." |
| Max heart rate, in bpm | No | A whole number from 80 to 230 | "Max heart rate is a whole number from 80 to 230." |

The two number limits are design defaults (not in the contract, since the numbers never leave the
phone); a change is a design pull request. Fields use `inputmode="numeric"` for the numbers, no
autocomplete for the nickname, and text is always inserted as text, never as markup.

**Remember on this phone.** A switch, **off by default**, that says its state in words ("On",
"Off"), never by colour alone. While it is off, the page writes nothing to `localStorage` (a test in
the screens issue). On, a valid FTP and maximum heart rate are written when Join (or Done, in My
numbers) is pressed. **Forget** (shown only while something is remembered) deletes both values from
`localStorage`, turns the switch off and clears the two fields. When the page opens and finds
remembered values it fills the fields, turns the switch on and shows Forget. Where `localStorage`
cannot be used (private window, blocked) the switch is shown disabled with the line "Not available
on this phone" and the page works without it.

## Content, in priority order (the class view)

Everything comes from `rider_state` and the rider's own numbers. The field is named in brackets.

1. **The zone** (`now.zone.number`, `now.zone.name`): number, name and colour on the gel. An FTP
   test label in the gel's label slot ("FTP test, 20 min", from `now.test`).
2. **Time left in the interval** (`now.remainingMs`): the countdown.
3. **The effort for the zone**, up to three rows: power, heart rate, RPE (next section).
4. **Position** (`now.position`): the word "Seated" or "Standing", beside the countdown; empty when
   `position` is null.
5. **The next intervals** (`next`, up to 3): zone chip (colour and number), zone name, length
   (`lengthMs`). With `next` empty: "End of class".
6. **Class time left** (`classRemainingMs`) and the rider's own nickname, in the top line.
7. **The one key**: **My numbers**, which opens the same fields as the entry form over the view.

**Visible at once**, in every connected state at every supported size: the gel's number and name,
the countdown, every effort row, the next rows and My numbers. Nothing scrolls. Check R11.

Not on the page, by rule or by contract: the cue, the song, the music link, the instructor's name,
any other rider's nickname, a rider count, a ranking, a comparison, a heart rate or power reading
of anyone. The page shows the rider's **own nickname** in the top line and nothing else about any
rider.

## The effort

Worked out on the phone by a pure module, `effort_calc` (ADR 0007 section 5), from the zone's
ranges in `rider_state` (`effort.ftpPct`, `hrmaxPct`, `rpe`, each `[low, high]` or null, copied from
the class's `zone_scale`) and the rider's numbers. Rounded to whole numbers, halves up.

| Row | With the rider's number | Without it | Null in the zone |
|---|---|---|---|
| Power | FTP × `ftpPct`: "220–235 W" (FTP 250, 88 to 94 %) | The percentages: "88–94% FTP" | Row not shown |
| Heart rate | Max heart rate × `hrmaxPct`: "157–170 bpm" (185, 85 to 92 %) | "85–92% max" | Row not shown |
| RPE | The range as it is: "7–8" | (the same) | Row not shown |

- **A row is shown for every range the zone has.** Without either number the page shows percentages
  and RPE, plus one grey line under the rows: "Add your FTP and max heart rate in My numbers to see
  watts and beats." (shown only while a percentage row stands in for a number the rider could
  give).
- **Never a zone colour** on any effort value (rule 7): the values are white (`--light-1`), the
  units grey (`--light-2`). The heart rate in beats per minute is **text**, a number taken from
  the planned zone's range, never a measured value and never a heart-rate zone (rule 7).
- **No advice** (rule 8): the page never says to go up, down or "adjust by your heart rate". It
  states the planned range.
- A range with equal ends is written once ("7"). A figure above 999 is not possible (FTP 600 ×
  150 % is 900).
- `effort_calc` has table tests (ADR 0007 section 6); the examples above are two rows of them.

## Layout

Sizes are shares of the viewport, one set per orientation, **the companion's tokens** (`--c-*` in
[companion.css](mockups/companion.css), companion.md "Size tokens"), so a rider's phone and the
instructor's read alike. The product sets them in `dvh` and adds `env(safe-area-inset-*)`. **Supported
sizes**: portrait from 360 × 640 to 430 × 932 and landscape from 640 × 360 to 932 × 430. Every
class state is checked at four sizes (390 × 844, 844 × 390, 360 × 640, 640 × 360); screenshots are
kept at the reference phone's two.

### Landscape (844 × 390 reference)

Two columns, 44 : 56, 3 vw apart. Left: gel, then the clock (the position word under the
countdown, on one line). Right: the effort, the next rows and My numbers at the foot. Sizes are the
companion's landscape tokens (numeral min(22 vh, 11.6 vw), countdown min(18 vh, 10.1 vw), values
min(8.2 vh, 4.3 vw), minor min(5.6 vh, 3.1 vw), labels min(4.4 vh, 2.35 vw)). Landscape is the
steadier way round on a handlebar mount; both are first-class.

### Sizes the page uses

The page's sizes are the companion's, a step larger, so every floored text keeps its 5 % margin
over R1's floors whatever whole pixel a browser rounds a cap height to. They replace the companion
tokens in the numbers above (`--c-hero`, `--c-value`, `--c-minor`, `--c-label`; the companion's
`--c-gel` stays):

| Token | Portrait | Landscape |
|---|---|---|
| `--c-hero` (countdown) | min(10.85dvh, 23.8vw) | min(18.9dvh, 10.6vw) |
| `--c-value` | min(5.05dvh, 10.4vw) | min(8.2dvh, 4.6vw) |
| `--c-minor` | min(3.4dvh, 7vw) | min(5.95dvh, 3.4vw) |
| `--c-label` | min(2.7dvh, 5.3vw) | min(4.7dvh, 2.7vw) |

The effort block's gap between rows is 1.1dvh in portrait and **1.4dvh in landscape**.

### Fitting text

- **Countdown**: as the companion: `M:SS` below 10 minutes, `MM:SS` to 99:59, `99+` above, digits
  in fixed cells (system.md, Type).
- **Zone name** (up to 80 characters): two lines at `--c-value`, then `--c-minor` over 24
  characters, two lines, then an ellipsis.
- **Nickname** in the top line: one line, ending in an ellipsis; it is shown whole in My numbers.
- **Effort rows**: a row never wraps. The longest, "675–900 W" and "184–230 bpm", fit beside their
  labels at every size (worst cases below).
- **Next rows**: chip and length always show; the name takes the rest and ends in an ellipsis.
- **A typed value** wider than its field scrolls inside it, as any input does.
- **Fitting steps**, only if the effort rows and the next rows do not fit: next rows three, then two,
  then one. The effort rows never go.

Worst cases ([worst](mockups/rider-worst-390x844.png), [no numbers](mockups/rider-worst-percent-390x844.png),
[form](mockups/rider-worst-form-390x844.png)): a 24-character nickname of wide capitals, an
80-character zone name, `58:58` and a class time of `1:58:58`, the FTP test label, three effort rows
with three-digit watts and beats, the longest hint, three 80-character next names.

## The one key and the keyboard

**My numbers** (at least 64 × 64 px) opens the form's number fields, Remember and Forget over the
view as a sheet; **Done** closes it. The view goes on underneath (the countdown keeps its time) and
is back on Done. While the sheet is open the effort updates as the rider types a valid number.
Nothing the sheet does is sent. There is no Leave key: the rider closes the page, and the instructor
sees the rider leave by the connection closing.

Touch targets: every key, field and switch is at least **64 × 64 CSS px** and **12 px** apart
(the companion's number: wet or gloved thumb, bouncing bike). Labels say what the press does.

## Motion and reduced motion

The page is calm, like the companion: between changes only the countdown's digits move.

- At an interval change the gel's colour crosses in `--m-change` (700 ms).
- Plates come and go in `--m-state` (300 ms).
- There is no beat dot, no flash, no hold bar and no animation on any key.

With `prefers-reduced-motion`, colour changes are instant and plates appear at once. No state relies
on motion. Nothing repeats faster than three times a second (check R9).

## Wording

Sentence case, plain words, one fact a line ([presenter.md](presenter.md) convention). No
exclamation marks and no generated text (rule 10). Link words and plates are white, grey and black.

| Where | Words |
|---|---|
| Top line | "Joined as Anna" (the nickname, one line, ellipsis); after a reload just "Joined", because the nickname is never stored; plates "Waiting for the instructor", "Reconnecting" |
| Countdown labels | "Interval left", "First interval", "Last interval", "Until the next song", "Interval left, not live" |
| Effort | "Power", "Heart rate", "RPE"; units "W", "bpm", "FTP", "max"; the hint |
| Keys | "Join the class", "Joining…", "Forget", "My numbers", "Done", "Try again" |
| Refusals | "Could not join. Check the code with your instructor." for every `cannot_join` |

## Measurable checks

On the mock-ups, [shoot.js](mockups/shoot.js) and [measure.js](mockups/measure.js) run these on every
rider shot (24 states; the class states at four sizes, the forms in portrait), using the companion's
text floors and [rider-checks.js](mockups/rider-checks.js); `ONLY=rider- node shoot.js` runs only
them. PL8's CI runs the same checks on the real page's screenshots, against recorded `rider_state`
messages, and prints the smallest margin over each floor per size and tier; every floored text must
stay at least 5 % over its floor there.

| Check | Requirement |
|---|---|
| R1. Text height | Cap height as a share of the **viewport height**, portrait / landscape, and never under the pixel floor (the companion's K1): zone numeral **8.5 % / 15.5 %**, 54 px; countdown **8 % / 13.5 %**, 48 px; values (zone name, position, **every effort value**, a typed value) **3.4 % / 6 %**, 21 px; next rows, units, class time, key words, plates **1.9 % / 3.4 %**, 12.5 px; labels and hints **1.5 % / 2.7 %**, 10 px |
| R2. Contrast | WCAG 2 ratio between the text colour and the worst rendered background pixel in its ink: **at least 7 : 1 for every text**, labels included |
| R3. No collisions | No two texts overlap; nothing wraps beyond its slot or is cut, except a designed ellipsis (the nickname in the top line, a long next name, a typed value) |
| R4. Touch targets | Every key, switch and field at least **64 × 64 CSS px**, at least **12 px** apart |
| R5. Actions | Every `data-action` is one of the page's own (`join`, `forget`, `remember`, `my_numbers`, `done`, `retry`); **none sends a command**, and none touches equipment (rule 2). No key moves the class |
| R6. One screen | No sideways scroll anywhere. Every class state and every ending state fits the screen with no vertical scroll; a form (the Join states and My numbers) may scroll down, since the keyboard covers much of a phone. Forms are checked in portrait |
| R7. Zone | The gel and every next chip carry the zone number; the gel and the next rows carry the name. No zone colour without its number. The effort rows carry no zone colour |
| R8. Hue | Hue only inside an element that stands for a zone. The plates, the switch, the fields, the keys and every state are white, grey and black (rule 7) |
| R9. Motion | With reduced motion, no transition or animation lasts longer than 0; nothing repeats faster than three times a second |
| R10. Coverage and tokens | Every text is inside a checked element; every colour comes from tokens.css; the fonts are the two of system.md, loaded from the page's own files |
| R11. Visible at once | In every connected class state: the gel's number and name, the countdown, the effort rows, the next rows and My numbers, all inside the screen |
| R12. No rider on the page | No canvas, picture, ring, bar, count, ranking or list of riders (rules 6, 13, 15) |

**Guards the screens issue adds** (ADR 0007 section 6): no request body or message from the page
holds FTP or maximum heart rate (a test over the recorded messages and the join body); the page
writes nothing to `localStorage` while Remember is off; `effort_calc` table tests; the nickname is
rendered as text only; the page sends `hello` and nothing else after joining.

## What the page never shows or does (plan section 3)

| Rule | How this page keeps it |
|---|---|
| 1. A finished class only | No editing, no choice of song or zone; it shows the class as written |

## Contract gaps and open questions

- **Nickname is not remembered.** ADR 0007 keeps FTP and maximum heart rate only. Default kept; a
  remembered nickname is a one-line addition in the screens issue if the owner wants it.
- **The FTP and heart-rate limits** (50 to 600 W, 80 to 230 bpm) are the page's defaults.
- **A typed class code** (the no-code state) is not in ADR 0007 section 5's list of states. It adds
  no field to the contract and gets the same `cannot_join`; the Orchestrator may drop it.
- **Wake lock wording** is the companion's, unmocked.
- None of this adds a field to `rider_state`, rider data to any message, or a token or code to a
  screen.
