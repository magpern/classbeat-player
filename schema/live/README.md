# Live sessions v1 (the handlebar companion)

The contract of [ADR 0005](../../docs/adr/0005-live-sessions-and-the-handlebar-companion.md),
section 4: every HTTP body and answer of the live routes and every WebSocket message of the
companion, as closed JSON Schemas (2020-12), with generated Python and TypeScript types and the
rule guards of section 7. ADR 0002 section 8 holds the credentials and limits around them.

## Layout

| Path | What |
|---|---|
| `v1/<name>.schema.json` | One schema per message and per HTTP body or answer. Every object is closed |
| `v1/routing.json` | The routing allowlist: each WebSocket message's schema, sender role and receiving roles; each HTTP route's body, answer and error codes |
| `v1/examples/<name>/valid/`, `.../invalid/` | Examples, read by both test suites; each invalid one breaks one thing |
| `guard/equipment-words.txt` | Words no live schema may hold (rule 2) |
| `guard/rider-words.txt` | Words no message delivered to a controller may hold (rule 13) |
| `guard/credential-words.txt` | Token, code, account and device words no message delivered to a controller may hold |
| `../generated/python/live_<name>.py`, `../generated/ts/live-<name>.d.ts` | Generated by `schema/generate.sh`, checked by `schema/check-generated.sh` |

Tests: `python/tests/test_live.py` (examples, generated models), `python/tests/test_live_guards.py`
(the rule guards, with the closed-shape check in `python/tests/live_shape.py`),
`ts/test/live.test.ts` (examples under Ajv, the action set, the closed-shape check in
`ts/test/live-shape.ts`, the generated types). The word lists are read by the Python suite.

| Schema | Where |
|---|---|
| `session-answer` | Answer of `POST /api/live/sessions` |
| `controller-request`, `control-request` | Bodies of `POST /api/live/controller` and `POST /api/live/control` |
| `controller-answer` | Answer of both controller routes |
| `error` | Every error answer of the live routes |
| `hello`, `welcome`, `host-status`, `controller-joined`, `controller-left`, `make-code`, `control-code`, `code-cancelled`, `drop`, `companion-state`, `command` (from a phone), `command-forwarded` (to the host, with `slot`), `command-result`, `ack`, `end`, `ended` | WebSocket messages, as `routing.json` routes them |

## Choices the ADR left open

1. **Field names are camelCase** across `live/v1`, as the ADR writes the messages (`expiresInMs`,
   `classMs`); the HTTP answers follow: `sessionId`, `joinCode`, `hostToken`, `controllerToken`.
   HTTP bodies and answers carry no `v` or `type`; every WebSocket message has `"v": 1` and a
   `type`.
2. **Short codes are sent in their shown form** `XXXX-XXXX` (ADR 0002 section 2's alphabet). The
   phone page normalises what was typed (case, spaces, hyphens) before it sends `session` or
   `code`; anything else fails the schema and gets 422 `invalid_request`, on the cookie route
   (`POST /api/live/controller`) as well. That answer depends only on the body's form, never on
   the session, so it tells nothing about who is there.
3. **Ids.** `id` and `run` are 16 bytes in base64url without padding (22 characters); `seq` and
   `basis` are integers from 0 to 2^53 - 1; times are integer milliseconds up to 24 hours.
4. **Link state names** are ADR 0001's, written in snake case: `locked`, `paused`, `coasting`,
   `off_the_list`, `ambiguous`, `manual`.
5. **Announcement kinds** are the player's fixed texts (`core/link/events.ts`,
   `core/link/while-following.ts`): `resynced_back` and `resynced_forward` with whole
   `seconds`, and `following_stopped` (the hand-over to the manual clock) with `seconds` null.
6. **`now` is always present**: a session exists only while a class is open, and a class has at
   least one interval.
7. **The schema holds two rules of section 5 as well**: `companion_state` cannot list `nudge`
   while `link.mode` is `following`, nor `undo_resync` while `canUndo` is false.
8. **`reason` is null exactly when `result` is not `refused`**, in `command_result` and `ack`.
   The host's `command_result` cannot give `host_away` or `rate`; only the server's `ack` can.
9. **`welcome`** gives `slot` and `hostConnected` to a controller only. Its `role` is `host` or
   `controller`: riders' messages come with the riders' issues. `hello` accepts the three
   prefixes of ADR 0002 (`cbp_hst_`, `cbp_ctl_`, `cbp_rdr_`).
10. **`sessions_full`** (409) is the answer of `POST /api/live/sessions` when the account already
    has 3 sessions on other devices (ADR 0002 section 8 sets the limit but names no code).
11. **Tokens in examples.** A token's 43-character secret is written `<secret43>` in the example
    files and built by the test loaders at run time, so no file holds a whole token.

## Validate with the schemas, not with the generated models

The generated Pydantic models and TypeScript types hold the fields, their types, enums, lengths
and ranges, but not the conditional rules (`if`/`then`/`else`, `not`): for example the
generated `Command` accepts `pause` with a `deltaMs` and `nudge` without one, and `Ack` accepts
`applied` with a reason. The live process, the player and the phone page validate every message
with the JSON Schema in `v1/` (Ajv, `jsonschema`) and use the generated types only for the
value that passed.

## The guards

- `command` and `command-forwarded`: `action` is exactly `start`, `pause`, `resume`, `skip`,
  `nudge`, `undo_resync`; `deltaMs` exactly `5000` or `-5000`, required with `nudge` and refused
  otherwise. The same list is the only one `companion_state.allowed` may hold.
- No property name, `$defs` key, `required` entry, enum or const value in any schema under
  `schema/live/` holds a word of `guard/equipment-words.txt` as a whole word (names split at
  `_`, `-`, spaces and case changes).
- What the server delivers to a controller (`welcome`, `host_status`, `companion_state`, `ack`,
  `ended`, pinned) holds no word of `guard/rider-words.txt` or `guard/credential-words.txt`. A
  controller sends only `hello` and `command`, to the server. No message reaches a rider.
- `control_code` goes to the host only, and no other message after `hello` has a token or code
  field. The phone's `command` has no `slot`; the forwarded one requires it; `ack` has none.
- Every live schema is closed, checked as an allowlist (`python/tests/live_shape.py`,
  `ts/test/live-shape.ts`): every subschema is a JSON object using only known keywords (no
  boolean schemas, `patternProperties`, `unevaluated*`, `dependent*`, `prefixItems`, `allOf`,
  `oneOf`); every shape is typed (a `type`, `const`, `enum`, local `$ref` or `anyOf` of typed
  branches, never `{}`); every object has `type` `object`, `properties` and
  `additionalProperties: false`; every array has typed `items` and `maxItems`. Both suites
  also show that the check refuses each of these openings.

The word lists only grow. Changing an expected list in a guard test is a rule-sensitive pull
request.
